# 개발 경위 및 산출물 보고서 — team-relay-mcp

## 1. 배경: 무엇을 풀려고 했나

팀 프로젝트에서 팀원 각자가 로컬 컴퓨터에서 Claude(Code)로 작업하던 중, 서로 이어지는 작업 사이에 확인이 필요한 내용이 생기면 다음과 같은 수동 루프를 반복하고 있었다.

> B의 Claude가 질문을 도출 → B가 복사 → 디스코드로 A에게 전달 → A가 복사해서 자기 Claude에게 붙여넣음 → 답변 생성 → A가 복사해서 B에게 전달 → B가 복사해서 자기 Claude에게 붙여넣음

이 "사람이 AI 사이를 오가며 복붙만 하는" 비효율을 없애는 것이 출발점이었다.

## 2. 검토 과정 (타임라인)

실제로는 한 번에 지금의 구조로 도달한 게 아니라, 여러 후보를 검토하고 조건을 좁혀가며 도달했다.

### 2.1 Claude Tag 검토 → 제외

Slack에 Claude를 팀원처럼 참여시키는 Anthropic 공식 기능. 채널 전체가 하나의 Claude를 공유한다는 컨셉 자체는 맞았지만,

- Team/Enterprise 플랜 전용 (베타)
- Slack 전용, 채널 작업은 개인이 아니라 **조직 계정으로 과금**

이라는 점에서 "각자 구독으로, 소규모 팀에서" 라는 조건과 맞지 않아 후보에서 제외했다.

### 2.2 커스텀 디스코드 봇 + API 키 구상 → 방향 수정

직접 디스코드 봇을 만들어 팀원별로 계정을 라우팅하는 구조를 처음 제안했다. 이때는 Claude API(Agent SDK, 종량제)를 호출하는 걸 전제로 했는데, 사용자가 "API로 하면 안 된다, 구독 플랜의 사용량을 써야 한다"고 명확히 정정했다. 이 시점에 핵심 제약이 확정됐다:

- **API 키/종량제 금지**
- **각자의 Pro/Max 구독 사용량으로 처리**

### 2.3 Agent SDK의 구독 로그인 방식 확인

찾아보니 Claude Agent SDK(Claude Code를 구동하는 엔진)는 API 키 대신 claude.ai 구독 계정으로 로그인해서 쓸 수 있고, 이 경우 사용량이 구독 한도에서 차감된다는 것을 확인했다. 이 조건을 만족하는 방향으로 재설계했다.

### 2.4 Claude Code Channels 발견 → 채택, 그러나 한계 확인

Anthropic이 공식으로 제공하는 **Channels** 기능(연구 프리뷰)을 확인했다. 실행 중인 로컬 Claude Code 세션에 디스코드/텔레그램 메시지를 실시간으로 밀어넣고, 응답도 같은 채널로 돌려보내는 양방향 브릿지다. 게다가 **claude.ai 로그인(구독) 인증만 지원하고 API 키는 지원하지 않아** 앞서 확정한 제약과 정확히 맞아떨어졌다.

다만 확인 과정에서 두 가지 한계가 드러났다.

- 이벤트는 **세션이 켜져 있을 때만** 받을 수 있고, 꺼져 있던 동안 온 메시지를 나중에 따라잡는 기능이 없다.
- 여러 팀원이 한 채널을 쓸 때 "이 메시지가 누구에게 온 것인지" 구분하는 규칙이 없다.

### 2.5 "이미 있는 서비스인지" 확인 → 없음

Channels를 그대로 쓰는 것 외에, 이 시나리오(2인 이상, 각자 로컬, 각자 구독, 자동 브릿지)를 통째로 패키징한 기존 서비스가 있는지 확인했다. 관련은 있지만 정확히 맞는 건 없었다.

- **Agent Teams**: 한 사람이 여러 에이전트를 병렬로 부리는 기능이지, 서로 다른 사람·계정을 잇는 용도로 검증되지 않음
- **OpenClaw**: 비슷한 컨셉의 서드파티 오픈소스지만 Anthropic 비공식이고 보안 취약점 이력이 있어 배제

### 2.6 "이러면 내가 개발할 게 없다" → 실제 개발로 전환

Channels만으로는 설정(봇 생성, 페어링, 플래그 지정) 수준이라 "개발"이라 부르기 어려웠다. 사용자가 "직접 개발을 가미해서 개인이 더 쉽게 할 수 있게" 해달라고 요청했고, 이 시점부터 계획서 형식이 아니라 **Channels가 못 하는 부분(오프라인 동안의 메시지 유실, 수신자 구분)을 메꾸는 작은 도구를 실제로 구현**하는 방향으로 전환했다.

## 3. 최종 아키텍처

```
[A의 PC]                                  [B의 PC]
Claude Code (A 계정 로그인)                Claude Code (B 계정 로그인)
        │  (MCP, stdio)                          │  (MCP, stdio)
        ▼                                         ▼
  team-relay-mcp 서버                       team-relay-mcp 서버
  (ask_teammate / reply / check_inbox)      (동일)
        │                                         │
        └──────────────┐         ┌───────────────┘
                        ▼         ▼
                 공유 디스코드 채널
        (메시지에 [TO:이름] 태그로 수신자 표기,
         채널 히스토리 자체가 대화의 원본 저장소)
```

핵심 설계 원칙:

- **API 키 없음** — 이 서버는 모델 호출을 전혀 하지 않는다. Claude Code가 이미 구독 계정으로 로그인되어 있으면 그 인증을 그대로 쓴다. 이 서버가 하는 일은 "메시지를 디스코드로 보내고 받아오는 것"뿐이다.
- **중앙 서버 없음** — 팀원 각자 자기 PC에서 이 서버를 띄운다.
- **디스코드 채널이 곧 데이터베이스** — 별도 DB를 두지 않고, 채널의 메시지 히스토리를 그대로 대화 기록으로 삼는다. 로컬에는 "내가 마지막으로 어디까지 읽었는지"(메시지 ID 커서) 딱 한 줄만 저장한다.

## 4. 파일 구성

```
team-relay-mcp/
├── README.md              사용법 전체 (봇 생성부터 트러블슈팅까지)
├── package.json            의존성: @modelcontextprotocol/sdk, discord.js, dotenv
├── package-lock.json
├── .env.example             필요한 환경변수 예시
├── .gitignore                .env, 로컬 상태 파일 등 제외
├── claude-md-snippet.md    CLAUDE.md에 붙여넣을 사용 지침
├── setup.js                 대화형 초기 설정 스크립트
└── src/
    ├── index.js             MCP 서버 본체 — 도구 3개 등록
    ├── discord.js            디스코드 래퍼 — 보내기 / 특정 시점 이후 히스토리 조회
    └── state.js               "마지막으로 읽은 메시지 ID"만 저장하는 로컬 상태 파일 관리
```

### 파일별 역할

| 파일                   | 역할                                                                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/index.js`         | MCP 서버 진입점. `ask_teammate`, `reply`, `check_inbox` 세 도구를 정의하고 stdio로 Claude Code와 연결한다.                                       |
| `src/discord.js`       | discord.js를 얇게 감싼 래퍼. 채널에 메시지를 보내는 것과, 특정 메시지 ID 이후의 히스토리를 가져오는 것 두 가지만 책임진다.                       |
| `src/state.js`         | 로컬 파일(`.team-relay-state.json`)에 "마지막으로 읽은 메시지 ID"만 저장/조회한다. 대화 내용 자체는 저장하지 않는다 — 원본은 항상 디스코드 채널. |
| `setup.js`             | 봇 토큰·채널 ID·팀원 이름을 대화형으로 입력받아 `.env`를 만들고, `.mcp.json`에 추가할 설정을 출력한다.                                           |
| `claude-md-snippet.md` | Claude가 세션 시작 시 `check_inbox`를 먼저 호출하고, 필요할 때 `ask_teammate`/`reply`를 쓰도록 유도하는 지침 원문.                               |
| `README.md`            | 디스코드 봇 생성(개발자 포털) → 설치 → `.mcp.json` 등록 → 세션 상시 유지 방법 → 트러블슈팅까지의 전체 가이드.                                    |

## 5. 설계에서의 트레이드오프

- **세션이 항상 켜져 있어야 실시간 수신 가능**: 이 자체는 Channels의 근본 제약을 그대로 물려받는다. 다만 `check_inbox`로 "꺼져 있던 동안의 누락분"은 보완했다.
- **연구 프리뷰 위에 얹은 도구**: Channels 자체가 아직 정식 기능이 아니므로, 향후 Anthropic 쪽 사양 변경 시 이 프로젝트도 손봐야 할 수 있다.
- **수신자 구분을 텍스트 태그(`[TO:이름]`)로 처리**: 간단하지만, 팀원이 실수로 태그를 빼먹거나 이름이 겹치면 라우팅이 안 될 수 있다. 팀 규모가 커지면 더 견고한 방식(예: 디스코드 스레드 활용)으로 바꿀 필요가 있다.
